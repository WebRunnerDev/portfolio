## Выбор: использовать

- Ржавчина `#B84530` — акцент в обеих темах. _Q27._
- Тёмная тема: `primary-text` `#DA6A52`, вторичный текст `#8A94A6`; токены `border`, `glow`. _Q27._
- Контраст текста AA. _[plan.md](plan.md)._
- Акцент сдержанный: графит доминирует; ржавчина — только главное действие, фокус, активный пункт навигации, ромбы. Свечение — только на hover/focus в тёмной теме. _Владелец, 2026-10-15._
- Углы: радиус 0; у ключевых элементов (карточки, главная кнопка) — срез угла под 45°, как грань ромба. _Владелец, 2026-10-15._
- Шрифты: обязательны казахская кириллица (ә ғ қ ң ө ұ ү һ і) и латиница с диакритикой; для `ar` — отдельный шрифт через `unicode-range`. _Q29, Q39._
- Темы: системная по умолчанию + переключатель. _Q17._
- RTL с первого дня; не зеркалятся лого, hero, плеер, блоки кода. _[ADR-0007](adr/0007-rtl-from-day-one.md), Q37._
- Анимации уважают `prefers-reduced-motion`. _[ADR-0005](adr/0005-motion-and-view-transitions.md)._

## Выбор: не допускать

- Surface без рамки: контраст Surface/BG ~1.12 — плоскости разделяются рамкой `border`. _Q20._
- Вторичный цвет `#4A5568` на тёмном фоне для текста (2.5:1) — только декор. _Q20._
- Светлая тема без акцента (Primary = Text). _Q20._
- Скруглённые «пилюли» и мягкие тени — противоречат острым граням. _Владелец, 2026-10-15._
- Постоянное свечение и ржавые заливки крупных блоков. _Владелец, 2026-10-15._

## Решения по ходу (2026-10-15)

- **Шрифты:** Tektur (заголовки), Onest (текст), Fira Code (код, метки), Readex Pro (`ar`). _Владелец._ Unbounded и JetBrains Mono отклонены: в их файлах (`@fontsource-variable` 5.3) нет ә ғ қ ң ұ һ — проверено по cmap.
- **`primary-text` в светлой теме — `#A83F2C`**, а не `#B84530`: исходная ржавчина на `surface-raised` даёт 4.31:1 (< AA). Заливки и кнопки остаются `#B84530`.
- **Hover главной кнопки — `#9A3826` в обеих темах**: светлый hover в тёмной теме не держит белый текст (4.39:1).
- **`glow` → `x-zsd.elevation.shadow-accent`** в цвете `primary-text` 40 %, только тёмная тема. Слово «glow» запрещено словарём формата, отдельный цвет-токен не нужен.
- **`border` → `x-zsd.border.color-default`** (`outline-muted`) и `color-control` (`outline`).
- **Disabled-текст — ≥ 4.5:1** (`#5F6672` / `#8C8C8C`), хотя WCAG этого не требует.

### Hero-эффект: Kinetic Grid

_На этапе 7 заменён Cast Lattice (#164), код Kinetic Grid удалён; раздел — история выбора._

Выбран владельцем из пяти кандидатов OriginKit; Black Hole, Particle Tunnel, Fluid Trail и Pixel Reveal не прототипировались по решению владельца. Kinetic Grid — canvas 2D без зависимостей, не WebGL.

Сравнивались два варианта:

- **Оригинал OriginKit** (`kineticgrid`, вариант framer, MIT; получен через MCP OriginKit): квадратная сетка, каждый отрезок — отдельный `stroke()` со своей прозрачностью, точки — `arc()`, след курсора; DPR не ограничен; без курсора неподвижен; `cursor: crosshair`; reduced motion не учитывает. Цвета палитры, настройки по умолчанию (шаг 30, радиус 400).
- **Прототип** по той же идее: решётка повёрнута на 45°, ячейки — ромбы, под курсором заливаются ржавчиной; без курсора по сетке идёт волна; все линии — один путь и один `stroke()` за кадр. Шаг 48.

Замер: Chromium с GPU, указатель движется по сетке, частота экрана выше 60 Гц; gzip после esbuild minify, без React.

| | Оригинал, DPR 2 | Оригинал, DPR 1 | Прототип, DPR 1.5 | Прототип, DPR 1 |
|---|---|---|---|---|
| Вес gzip | 1.8 KB | | 1.2 KB | |
| 1440×900, CPU ×1 | 40 fps | 46 fps | 39 fps | 100 fps |
| 1440×900, CPU ×4 | 37 fps | 39 fps | 39 fps | 94 fps |
| 390×844, CPU ×4 | 100 fps | 100 fps | 88 fps | 100 fps |
| 390×844, CPU ×6 | 88 fps | 86 fps | 92 fps | 98 fps |

Выводы для #117:

- На большом вьюпорте оригинал упирается в ~2900 отдельных `stroke()` за кадр, и DPR 1 его не спасает. Отрезки рисуются пачками — одним путём, как в прототипе (или по корзинам прозрачности).
- Рисуем при DPR 1 (в пределах ADR-0006 «DPR ≤ 1.5»): тонкие линии и плоские заливки от этого не теряют.
- Берём из прототипа ромбическую решётку, заливку ячеек и волну без курсора; убираем `cursor: crosshair` (курсор не меняем) и след курсора; добавляем reduced motion и паузу вне вьюпорта.
- Замер — на GPU этой машины; слабый GPU проверяется в #125, FPS-проба ADR-0006 остаётся страховкой.

### Решения

- **Плавный скролл (Lenis): нет.** Вес и JS на каждом кадре, конфликты с якорями, `scrollRestoration` TanStack, поиском по странице и нативной инерцией тачпадов и мобильных. Вес движению дают reveal-анимации и кривые. ADR-0005 не меняется, отдельный ADR не нужен. _Владелец._ _Пересмотрено 2026-11-18: Lenis есть, но только на `full` и с точным указателем (ADR-0014, «Главная на Swarm › Путь к 10 › Выбор владельца»)._
- **Кастомный курсор: нет** (по умолчанию `top-design`, согласия владельца нет). _Пересмотрено на этапе 7: нативный курсор остаётся, рядом с ним — ромб (см. «Арт-дирекция этапа 7»)._
- **Кривые:** expo out — вход, quart out — hover, expo in-out — перестановка ромбов, expo in — уход; ключевые слова `ease`/`linear` запрещены. Старые `easing-standard`/`easing-exit` заменены; `src/styles/tokens.css` перегенерируется и использования переводятся в #112.
- **Display:** `display-lg` 168px (10.5:1 к `body-md`), трекинг −0.04em, вес 800; ниже `lg` — `display-sm` 72px и ручной перенос «Web / Runner». Бренд латиницей во всех Lang, длинных kk/de слов в нём нет; переносы kk/de проверяются на заголовках страниц (`hyphens: auto`). Для Readex Pro трекинг 0.
- **Хедер:** всегда видим (единственный путь к меню), на главной лого и название пустые, пока ромбы в hero. **Футер:** контактная секция с крупным заголовком и почтой как главной ссылкой.
- **Детали:** `::selection` — `primary` + `on-primary` (5.3:1) в обеих темах; фокус — сплошной квадратный контур, на срезанных элементах идёт по срезу; hover карточки — рамка `primary`, ромб в срезанном углу, сдвиг заголовка на 4px, без теней и масштаба. Свечение остаётся только у главной кнопки в тёмной теме.

### Hero

- Высота: вьюпорт минус хедер (`svh`, чтобы не прыгал от панелей мобильного браузера), не меньше 480px.
- Асимметрия: бренд «WebRunner» от начального края контента; 7 ромбов лого — у его конечного края, на высоте прописных. Подзаголовок под брендом, с `lg` смещён на четверть ширины контента (до начала контента секций): реальное имя (Brand) и заголовок из Profile, `body-lg`, `text-wrap: balance`.
- Главное действие — CV; второе — проекты.
- Бренд: `display-lg` 168px на `xl`, плавно (`clamp`) до `display-sm` 72px на 320px; ниже `lg` — две строки «Web» / «Runner», перенос вручную. Латиница и LTR во всех Lang.
- Эффект tier занимает весь hero за текстом и выходит за `content-max` до краёв вьюпорта; `aria-hidden`.
- Не зеркалятся эффект и раскладка ромбов внутри лого; текст, действия и место ромбов следуют Direction.

### Hero-эффект (tier `full`)

- С ADR-0013 `full` на главной — Swarm на всю страницу («Главная на Swarm»). До него — Cast Lattice на WebGL2 (с этапа 7, #164): решётка литых призм-ромбов, под указателем вздымается, без него по ней слева направо идёт зыбь, так что на тач-экранах она тоже живёт. Сцена и замер — «Арт-дирекция этапа 7 › Cast Lattice». До #164 здесь был Kinetic Grid на canvas 2D.
- Hero не зеркалится, в `ar` направление то же.
- `lite` — SVG-анимация ромбов лого, `static` — hero со Swarm в покое неподвижной картинкой (`scripts/generate-hero-static.mjs`). До #185 это был Cast Lattice в покое.

### Ритм главной

Плотные ↔ воздушные, крупные ↔ камерные секции, отступы не одинаковые:

1. **Hero** — воздушный, крупный: одно высказывание и пустой графит.
2. **Резюме** — камерный: короткий абзац «Обо мне» `body-lg` в `prose-max`, смещён как подзаголовок hero; под ним последние три места работы (период, должность, компания), под ними образование (период, учебное заведение, степень) и технологии по категориям, с `lg` рядом; ссылка на полное резюме и скачивание PDF; сверху `section-lg`.
3. **Проекты** — плотный: все проекты списком без обложек — название, статус, описание в две строки, технологии; строка с Case Study ведёт на страницу проекта.
4. **Галерея** — воздушная: один баннер-переход в галерею (карточка): призыв, число альбомов и фото, три обложки.
5. **Блог** — плотный, камерный: последние три поста (дата, заголовок), без обложек; ссылка «Все публикации». Нет постов — секции нет.
6. **Футер** — снова крупный: заголовок контактов закрывает страницу.

Заголовок секции — `headline-lg`; над ним индекс главы крупной цифрой Tektur (`display-sm`, с `lg` до `display-md` 120px), `outline-muted`, `aria-hidden`, sticky вместе с заголовком — второй такт типографики после hero (#166). Индекс один: маленький `label-mono` на линии главы повторял крупную цифру и убран. Ржавый ромб ушёл с линии, где стоял одиноко, и закрывает цифру как точка, как в заголовке футера («03◆»): выезжает с ней из-под маски и проворачивается из ничего на середине подъёма. _Владелец, 2026-11-12._ В конце секции — одна ссылка в её раздел.

Секция открывается как глава: волосяная линия `outline-muted` во всю ширину контента. С `lg` контент делится на четыре колонки через `xxl`: заголовок занимает первую и остаётся видимым под хедером (`sticky`), пока секция прокручивается; контент — остальные три, на одной оси с подзаголовком hero. Так смещение hero продолжается через всю страницу. Треть давала слишком большой разрыв между заголовком и контентом. _Владелец, 2026-11-02._ Исключение — галерея: заголовок над баннером, баннер во всю ширину — воздушный такт ритма. _Агент, 2026-11-02, `top-design`._

### Хедер

```
┌─────────────────────────────────────────────────────────────────────┐
│ ◆◆ WebRunner │ ◆ PROJECTS                  EN ▾   ☾    [◆ Menu]    │
└─────────────────────────────────────────────────────────────────────┘
```

- 56px, `surface-raised`, нижняя рамка. Sticky и всегда видим: не прячется при скролле — в нём единственный путь к меню.
- Текущий раздел — `label-mono` с маленьким ржавым ромбом перед ним.
- Кнопка меню — `button-secondary`, иконка из трёх ромбов, текст «Menu» с `sm`.
- На главной лого в хедере пустое, пока лого hero во вьюпорте; когда hero уходит, ромбы переезжают в хедер (`easing-layout`), при возврате — обратно. При reduced motion лого в хедере всегда.
- Название в хедере на главной ждёт лого: пока ромбы в hero или в полёте, его нет (его говорит бренд hero), на последних 15% ухода hero оно выезжает из-под садящегося лого. Иначе лого, остановленное скроллом посреди полёта, лежит на названии и выглядит как баг. _Владелец, 2026-11-11._ Фокус с клавиатуры на ссылке показывает название сразу.
- Меню, открытое посреди полёта, разворачивает ромбы из того места, где лого видно сейчас (летящее лого хедера или ромбы hero), а не из пустого слота, и сворачивает их туда же.
- Индикатор прокрутки (#167): ржавая волосяная линия `primary` поверх нижней рамки, `scaleX` от начального края по `scroll(root)` один к одному со скроллом (`linear`: это положение, не движение), в RTL — от правого края; на всех публичных страницах, `aria-hidden`. Без `animation-timeline` её нет. При reduced motion остаётся: своего движения у неё нет. Пока открыто меню или меню Lang (они висят с той же рамки), линия гаснет. Контраст к `surface-raised` — 3,1:1 в тёмной теме, 4,3:1 в светлой.


- Футер — контактная секция каждой страницы: сверху `section-lg` и рамка.
- Метка `label-mono`, затем заголовок `display-sm`. Его точка — ржавый ромб: проявляется за последним словом, поворачиваясь из ничего (`easing-layout`, `duration-slow`). Это сигнатурный момент футера; при reduced motion ромб просто стоит. _Агент, 2026-11-09, `top-design`._
- С `lg` почта и контакты стоят на оси подзаголовка hero и контента глав главной (четверть ширины контента): смещение страницы доходит до её конца.
- Почта — ссылка `headline-md`, рядом копирование; результат копирования — рядом с кнопкой (как сейчас).

### Хореография загрузки главной

Одна последовательность, заканчивается к `choreography-max` (1200 мс). Каждая анимация отвечает на вопрос «зачем она движется»: откуда вещь пришла, куда уходит или что отвечает пользователю; нет ответа — анимацию убрать. Движение — как масса, набирающая скорость: резкий старт, долгая мягкая остановка.

| Время | Что появляется |
|---|---|
| 0–200 мс | Структура: хедер, линии сетки hero, рамки |
| 200–600 мс | Слова бренда выезжают снизу из-под маски, через `stagger-word` (60 мс) |
| 200–700 мс | Ромбы лого собираются по одному у конца бренда, `easing-layout` |
| 400–800 мс | Подзаголовок |
| 600–900 мс | Действия и контролы хедера, через `stagger-item` (80 мс) |
| 800–1200 мс | Остальное: запускается эффект hero, первая секция под сгибом |

- Строки и слова выезжают из-под маски, не проявляются блоком.
- Другие страницы так же показывают только заголовок страницы.
- Секции под сгибом появляются один раз при входе во вьюпорт, элементы внутри — через `stagger-item`.
- Ничего не блокирует ввод: ссылки и кнопки работают во время последовательности.
- От позиции скролла зависит только декор (ромбы в хедер); текст со скроллом не движется.
- Reduced motion: сразу конечное состояние; контент никогда не остаётся скрытым, если анимация не запустилась.

### Детали

- **Hover карточки:** рамка `primary`, ромб в срезанном углу, заголовок сдвигается на 4px по направлению чтения; `duration-fast`, `easing-hover`. Без масштаба и без теней.
- **Фокус:** сплошной контур с квадратными углами, `focus-width`/`focus-offset`/`focus-color`, без перехода. На срезанных элементах контур рисуется на внутреннем слое или SVG рамки и идёт по срезу, а не прямоугольником вокруг.
- **`::selection`:** `on-primary` на `primary` (5.3:1) в обеих темах, в блоках кода тоже.
- **Типографика:** `hyphens: auto` и `overflow-wrap: anywhere` на заголовках страниц — проверить kk/de на 320px; для Readex Pro трекинг 0.
- **Статус «В работе»:** не зелёная заливка, а контур `primary` с текстом `primary-text`, того же размера, что нейтральный «Завершён»; вместо иконки — ржавый ромб, который дышит, как горящий узел паутины (opacity и scale, `easing-layout`; при reduced motion просто горит). ### Cast Lattice (слой full в hero)

- Решётка Kinetic Grid: шаг 48, ромбические ячейки, те же, что в статичной картинке. Каждая ячейка — низкая призма-ромб, верхняя грань срезана под 45° по рёбрам, как срезы кнопок и карточек.
- Свет: скользящий направленный и rim по рёбрам, плоский Lambert в шейдере; без PBR и env-карт. Цвета — из токенов, перечитываются при смене темы: грани `surface`/`surface-raised`, рёбра `outline-muted`, блик `outline`, гребень `primary`.
- Указатель (мышь, перо) — давление: призмы в радиусе ≈ 4 шагов наклоняются от него и поднимаются, с пружиной; на гребне `primary` — всегда единицы ромбов, не заливка. В светлой теме ромб на гребне — сплошной `primary` с освещением, не полупрозрачный: розового не будет.
- Без указателя (тач) — волна-зыбь слева направо, как у Kinetic Grid. Не зеркалится в `ar`.
- Скролл через hero: поле наклоняется (pitch от прогресса hero, `easing-layout`), семь ромбов лого поднимаются из поля в ромбы hero и передают эстафету CSS-ромбам, которые долетают до хедера. Текст со скроллом не движется.
- Появление: crossfade поверх `lite` после первого кадра, `duration-slow`, `easing-enter`. Падение FPS, потеря контекста, ошибка — назад в `lite` без следов в консоли.
- `lite`: дышащие ромбы лого (как сейчас) и полёт ромбов в хедер на CSS. `static`: картинка решётки, ромбы сразу в хедере.

#### Реализация (#164)

- `src/pages/home/lib/cast-lattice/`, чанк `hero-full` ≈ 4 KB gzip. Призма: верх, четыре фаски 45° (5px) и стенки; одна инстансная отрисовка на кадр. Камера — над центром канваса на расстоянии 1,6 высоты: при z = 0 единица — CSS-пиксель, так что решётка в покое лежит там же, где в картинке `static`.
- Давление: у каждой ячейки своя пружина (≈ 2,4 Гц, затухание 0,42) на подъём до 28px и наклон до ≈ 28° от указателя, в радиусе 4 шагов; считается на CPU и уходит в буфер одним `bufferSubData`, только пока указатель на канвасе или пружины не успокоились.
- Ржавчина: 30% ячеек могут загореться; ячейка загорается выше 75% подъёма и гаснет ниже 60% (гистерезис), ромб растёт из центра от трети размера за ≈ 120 мс, без «пылинок». Неподвижный указатель оставляет целые ромбы, не обрезки; за движущимся — короткий след из нескольких.
- Зыбь: полоса шириной 4 шага и высотой 10px за 10 с; горят 4% ячеек, каждая целиком и на своей высоте полосы, поэтому одновременно видно несколько ромбов.
- Свет: ключевой — сверху слева, 38°, качается на ±25° за 16 с; грань — `surface`, светлее к свету и темнее от него на шаг `surface` → `surface-raised`, поэтому верх в покое — цвет страницы. Rim-свет скользит из-под горизонта с другой стороны и зажигает рёбра `outline` у наклонённых призм. Ржавые призмы — сплошной `primary` × освещение.
- MSAA включён: без него у наклонённых ржавых призм видна лесенка. DPR ≤ 1,5. Шейдеры — через `KHR_parallel_shader_compile`, где он есть, решётка раскладывается порциями между задачами.

#### Скролл через hero (#165)

- Прогресс — `exit` view-таймлайна hero, тот же, что у полёта ромбов; сцена считает его из прямоугольника канваса раз в кадр, не на `scroll`, поэтому на тач-экранах тоже.
- Наклон: поле поворачивается вокруг своего нижнего края, верх уходит от камеры, до 50° к концу `exit` по `easing-layout`. Камера на месте, поэтому в покое ничего не сдвигается. Сверху поле не кончается (видимая полоса hero сужается быстрее, чем поле уходит), а с боков решётка раскладывается шире канваса на 12% его ширины. Указатель проецируется на наклонённое поле: давление остаётся под ним.
- Подъём: на `full` первая доля `exit` (до 30%, меньше, если ромбы hero близко к хедеру: им остаётся четверть пути до него) — копии семи ячеек поля. Они стартуют с ячеек под лого (узор лого на 40% высоты hero ниже), по колонкам слева направо, поднимаются и наклоняются по пути, уменьшаются до ромба лого и к 90% доли ложатся под ромбы hero плоско и в их цвете. Ромбы hero лежат поверх канваса и закрывают их, так что стык без скачка в позиции и цвете при любом кадре скролла.
- Полёт ждёт подъёма: канвас ставит `data-rise`, когда подъём включён (только на самом верху страницы, чтобы ничего не прыгнуло), и CSS сдвигает swap и начало полёта на долю подъёма (`--logo-flight-rise`) от места ромбов в этот момент (`--logo-flight-rise-y`); их пишет `useLogoFlight`. Если hero выше видимой области и ромбы доходят до хедера раньше `exit`, доля — 0 и полёт идёт как в `lite`. Сцена упала в `lite` — `data-rise` уходит вместе с канвасом.
- Чанк `hero-full` — 5,5 KB gzip.

Render Delay во всех восьми прогонах один и тот же (`/ar` 1650 мс, остальные 1500 мс), меняется только TTFB — 670–855 мс, хотя документ один и тот же (2,3 KB). TTFB сдвигается вместе на всех страницах одного прогона, то есть это скорость машины. CSS вырос на 1 KB (18,6 → 19,6 KB transfer) и Render Delay не сдвинул. Локально по 10 замеров на сборку: `/ar` 2,38 / 2,41 / 2,36 с, `/en/cv` 2,20 / 2,21 / 2,21 с (до #161 / после #163 / `main` на #177).
- **`/ar` стабильно на 0,15 с дольше остальных** (Render Delay 1650 против 1500 мс). Наблюдаемые FCP и LCP у `/ar` и `/en` одинаковые, разница появляется в симуляции. Арабский шрифт Readex Pro стартовал только после рендера приложения и задерживал FCP на `/ar` на один такт. С #169 он предзагружается только на `ar` (`data-lang`, `contracts/lang-preloads.ts`): FCP `/ar` 1,92 → 1,78 с, LCP не изменился (2,37 → 2,38 с, 10 замеров). Оставшиеся 0,15 с сидят в пессимистичном графе Lantern (LCP — среднее оптимистичного и пессимистичного), запросы в нём те же, что у `/en`; источник не найден.
- **Отсюда правило:** `/ar` — самая узкая страница, запас 0,09 с по проверке и 0,07 с по медиане. Эффект, который добавляет работы до LCP на всех языках, проверять сначала на `/ar`. Шум между прогонами — до 0,1 с по лучшему из трёх, поэтому разницу меньше 0,1 с в одном прогоне за регрессию не считать.

## Главная на Swarm (2026-11-16)

Владелец выбрал прототип D7 «Рой» из `spike/home` (ветка `spike/home-prototypes`, README › D5–D7). Архитектура, уровни качества и понижение описаны в [ADR-0013](adr/0013-swarm-quality-levels.md). Здесь — сцена и как она ложится на главную. Фон за текстом и дизайн блоков правим по ходу переноса, без новых прототипов. _Владелец, 2026-11-16._

### Сцена
- **Сеть** (из D5). Нити натянуты, без провиса, тонкие и холодные. Трафик — короткие импульсы в шейдере нити: горячая голова и хвост, который остывает до ржавчины, без шариков. Свет только в узле, куда пришёл пакет.
- **Узлы.** Каждый — скруглённый ромб из холодных частиц, освещённый как твёрдое тело: Lambert от ключевого света и rim по краю. Около 22 % частиц сидят внутри ромба и дают глубину. Пакет сдувает пыль с грани, куда вошла нить: волна по поверхности от точки входа, короткий выброс у грани и вспышка ржавчиной, затем пыль оседает обратно. Свежий сильный всплеск не перезапускается слабым. Дальние узлы — маленькие ромбы в глубине, с туманом; от нагрева их пыль пушится.
- **Указатель** (мышь, перо) раздвигает пыль на экране с лёгким завихрением (радиус растёт с шириной вьюпорта), блоки лого клонятся к нему на пружине и в покое дышат; он же щиплет нити, которые пересекает: по нити бежит волна, от места касания расходятся импульсы. На тач-экране этого нет, вместо этого касание по паутине — пакеты из ближайшего узла.
- **Краулер.** Один бегун обходит видимые узлы. Если указатель активен, бегун идёт к нему. Фоновые пакеты прыгают между видимыми узлами.
- **Цвет.** В тёмной теме — сталь, ржавчина на вспышках и голове пакета, свечение. В светлой — пыль темнее фона, нити `outline`, вспышки `primary`, без свечения и аддитива (ADR-0013 › Темы).

### На главной
- **Hero.** Бренд, подзаголовок и действия — как сейчас, h1 остаётся LCP. Лого из пыли стоит в полосе под действиями, у конечного края (30 % высоты hero с `lg`, 24 % ниже), вокруг него паутина hero. Не на месте больших ромбов `lite`: тот квадрат лежит под брендом, и светлая пыль там спорит с текстом. _Агент, 2026-11-16, по кадрам #183._ Ниже `sm` квадрат стоит под действиями, поэтому текст hero держит под ним полосу (квадрат + отступ снизу + `spacing-xl`), и центрирование поднимает текст. Иначе на телефонах ниже ≈ 700 px верхний блок заходил за «See projects». Размеры считаются от наименьшей высоты hero и не зависят от tier: текст не сдвигается, когда `lite` сменяется на `full`. С `sm` квадрат у конечного края до действий не дотягивается, и полоса только увела бы его под сгиб. На 320×568 hero выходит на 31 px выше экрана, низ лого — на 10 px за краем. _Агент, 2026-11-17, по приёмке #182._ В мете hero живая строка обхода (из E): «Crawling · N nodes» — сколько узлов паутины hero обход уже зажёг, после него — «Indexed · N nodes». Только на `full`, `aria-hidden`, моноширинная, не переводится. _Агент, 2026-11-16, по #184: счёт узлов вместо путей сайта — строка говорит о паутине, которую видно._
- **Загрузка слоя.** После гейта ввода канвас проявляется с пылью, разбросанной по всему экрану, а ромбы `lite` за то же время гаснут. Обход в ширину зажигает паутину hero от её середины, пока пыль ещё разбросана; затем пыль собирается в лого за ≈ 1,3 с (`easing-layout`), и паутина стягивается к нему. Полноэкранного лоадера нет.
- **Главы.** У каждой главы главной (Резюме, Проекты, Галерея, Блог) свой блок из семи. Блок прилетает из лого hero на рельс главы, когда глава входит во вьюпорт. Краулер спускается к нему по одной нити от лого, без пучка у края, и обходит паутину главы. Паутина ниже hero — только по краям и между главами: под текстом её нет.
- **Футер.** Все семь блоков собираются в лого у футера, паутина футера обходится вся один раз при входе.
- **Как это легло на главную** (_агент, 2026-11-17, по #186_):
  - Рельс главы — точка её цифры (_с #203_): квадрат `0,42em` по центру ржавого ромба `chapter-stop` в `HomeSection`. С `lg` цифра в липкой колонке над заголовком, ниже `lg` и у широкой главы (Галерея) — над заголовком в строке. Прежний квадрат в конце строки цифры (ниже `lg`) и под заголовком (с `lg`) убран. Главы забирают блоки 0–3 по порядку показанных; цепочка идёт 6 → 0 → 1 → 2 → 3, это соседние ромбы лого, и пока блоки в лого, цепочка — его же нити. Видна только до последнего прилетевшего блока.
  - Блок летит по скроллу, а не по времени: от верха рельса у низа вьюпорта до полувьюпорта выше (`easing-layout`), вверх — обратно. Лого hero, ушедшее далеко вверх, блок ждёт сразу над вьюпортом и прилетает сверху, а не через всю страницу. Нити привязки блока гаснут, как только он трогается, и появляются при посадке: в полёте блок тянет только цепочку. Привязки к паутине главы гаснут, когда липкий рельс уезжает по длинной главе и они растягиваются больше чем на полвьюпорта.
  - Паутина главы привязана к секции, а не к рельсу, и раскладывается вне общего прямоугольника её текста: по краям и в зазоре над главой. Глава, которой ещё нет на странице, получает паутину по прикидке; узлы и так отходят из текста. Между соседними частями три длинные нити, по одной на треть ширины.
  - Параллакс глубины: узел глубже на 13 единиц отстаёт от скролла на 42 %. У hero — от верха страницы, у футера — до конца страницы, так что в покое оба как разложены; у глав — вокруг середины вьюпорта.
  - Квадрат лого футера (`data-swarm-anchor="footer"`) занимает место, только пока сцена идёт (index.css), с `lg` — в первой колонке рядом с контактами, ниже — над подписью. Блоки собираются от верха квадрата у низа вьюпорта и успевают к концу страницы.
  - Нити, у которых оба конца далеко за одним краем экрана, не раскладываются и не рисуются; разложенные идут в буферах подряд, и на GPU уходят только они. Пыль группы, у которой нет узла у экрана, не рисуется. Узлов на странице около 200, нитей около 410, а на программном WebGL сцена держится почти как с одной паутиной hero. Замер (GPU, CPU ×4, прокрутка всей страницы вниз и вверх, 700 px/с): 1440 × 900 — 52–59 fps, 390 × 844 — 55 fps; чанк full — 17,5 KB gzip.
- **Уровни качества** (_агент, 2026-11-17, по #187_):
  - Уровень выбирает чанк full при первом старте сцены за визит (`lib/swarm/quality.ts`), держит в своей памяти и пишет на канвас (`data-quality`). Счёт FPS идёт с первого кадра сцены, вместе с интро: устройство, которое не держит сцену, не ждёт конца интро.
  - При понижении финиш остаётся каким был, как и пыль дальних узлов: `mobile`, спустившийся в `mobile-lite`, идёт через пост до следующего старта. Без поста стартует только сам `mobile-lite`: буфер глубины канваса задаётся при создании контекста.
  - Закрепить уровень — параметр `?swarm=<уровень>` (e2e, приёмка). Его читает только чанк full. Закреплённый уровень не понижается и по FPS в `lite` не уходит; потеря контекста по-прежнему уводит.
- **Касание** (_агент, 2026-11-17, по #188_):
  - Тап — нажатие, которое отпустили в пределах 10 px и 500 мс от места нажатия. Касание, которое стало скроллом, браузер отменяет (`pointercancel`), и пакетов нет. Так же для мыши и пера: клик шлёт пакеты, выделение текста протяжкой — нет. Второй палец отменяет нажатие.
  - Не считается тапом по паутине нажатие на ссылку, кнопку, поле, `summary`, элементы с ролями кнопки, ссылки, пункта меню, вкладки, диалога и на хедер: он непрозрачный, паутины за ним не видно. Chromium засчитывает касание в нескольких пикселях от ссылки ссылке; тогда пакетов тоже нет.
  - Узел — ближайший на экране в радиусе 180 px, у которого есть видимая нить. Вспыхивает (нагрев 1), блок сдувает пыль спереди с силой 1,1, по каждой видимой нити уходит пакет на 4–6 прыжков. Эти пакеты не упираются в лимит фоновых (14), только в общий пул (192). Тап до конца интро ничего не шлёт.
  - Замер INP тапа (390 × 844, CPU ×4, Chromium с GPU): `mobile` — 56–80 мс, `mobile-lite` — 16–32 мс. В e2e на программном WebGL при 4 ядрах — 32–72 мс, при двух таких тестах параллельно — до 176 мс.
- **Текст.** Узлы отходят из зон текста к ближайшему краю, нити там гаснут, ничего не затемняется. Маска включается после появления текста.
- **Не переносится.** Док роя в лого хедера: хедер непрозрачный, полёт CSS-ромбов (#158) остаётся. Подъём копий Cast Lattice (#165) тоже не переносится.
- **`lite` и `static`.** `lite` — дышащие ромбы лого, как сейчас. `static` — кадр hero со Swarm в покое, по WebP на тему, вместо Cast Lattice. Кадра два: горизонтальный (1440 × 900) и портретный (390 × 844), так что лого стоит там же, где его кладёт сцена. Каждый не больше 11 KB: пыль — попиксельный шум, и в 7 KB прежней картинки кадр мутнеет. Картинка грузится лениво и только при `static`. _Владелец, 2026-11-16, по #185._

##### Выбор владельца (2026-11-18)

Владелец посмотрел прототипы (ветка `spike/path-to-10`, #199) на компьютере и телефоне. Взвешенный скролл и переход пылью описаны в ADR-0014. _Владелец, 2026-11-18._

- **Скролл — `heavy`.** Lenis 1.3.27 с `lerp` 0,065, на всём сайте, но только на tier `full` и с точным указателем (`pointer: fine`). На касании, на `lite`, на `static` и при reduced motion прокрутка браузерная. Lenis двигает само окно (`scrollTo` на каждом кадре), без `transform`, поэтому scroll timelines, чтение раскладки сценой и восстановление прокрутки видят обычный скролл. Якоря (skip link) прыгают по-браузерному. Пока открыт оверлей Radix, Lenis стоит. На смене страницы плавная прокрутка обрывается, позицию ставит роутер. Чанк ленивый, около 5,4 KB gzip, стартовый JS не растёт. Причины прежнего отказа (выше, «Решения») проверяются в тикете по одной.
- **Переход — `dust`.** Уход с главной, пока сцена идёт: пыль лого и блоков разлетается над новой страницей за 900 мс, вспыхивает и гаснет, потом канвас уходит. Для этого канвас живёт под `<body>`, вне дерева React, и переживает размонтирование главной. View Transition на таком уходе нет: переход несёт сама сцена. Все остальные смены страниц, уход с главной без сцены (`lite`, `static`, reduced motion) и переход на главную идут через View Transition, как раньше. Занавес из ромбов (`curtain`) не берём.
  - _Агент, 2026-11-18, по #204._ Канвас создаёт `HomeFull` под `<body>`, React держит только невидимый элемент над вьюпортом, за которым следит `usePlaying`. На уходе канвас сразу перестаёт быть канвасом главной (снимаются `data-effect` и `data-swarm-scene`): квадрат лого в футере новой страницы не держит место, а главная, на которую вернулись через Back, раскладывает свою сцену рядом. Через 450 мс канвас гаснет за `duration-slow`, через 900 мс канвас снимается со страницы, и сцена отдаёт контекст WebGL. Если вкладка скрыта или контекст потерян, кадров нет, и сцена уходит по таймеру. View Transition пропускается, если путь уходит с `/{lang}` на страницу глубже и на странице есть `[data-swarm-scene][data-ready=true]` (`leavesHome` в `shared/lib/view-transition`). Смена языка на главной идёт через View Transition, как раньше. Замер (GPU, CPU ×4, 390 × 844, клик «All projects»): INP 72–120 мс, на `main` 72–104 мс; после ухода под `<body>` канвасов нет. Чанк full 19,6 KB gzip (было 19,0).
- **Цифры глав — `stop`.** Блок главы садится в цифру главы как её точка: на место ржавого ромба после цифры (`chapter-stop`), который даёт ему место и уходит, пока сцена идёт. Без сцены (`lite`, `static`) ржавый ромб стоит как сейчас. Квадрат рельса в конце строки больше не якорь. Обводка цифры пылью (`outline`) и цифра из пыли (`fill`) отпадают, и выборка глифов (`glyph.ts`) в `main` не идёт.
  - _Агент, 2026-11-18, по #203._ Отступ ромба от цифры `0,34em` стоит на любом tier, а не только со сценой, поэтому цифра не сдвигается, когда `lite` сменяется на `full` (CLS 0). Пока сцена идёт, ромб прозрачный (`:root:has([data-swarm-scene][data-ready="true"])`). Якорь стоит по центру ромба: `inset-0 m-auto` в прототипе прижимал квадрат шире ромба к его началу. В RTL точка у конечного края цифры, слева. Замер прокрутки через всю главную (GPU, CPU ×4): 1440 × 900 — 57,5 fps (`main` 58,2), 390 × 844 — 54,4 fps (`main` 54,5).

##### Причины отказа от Lenis, проверка (#205)

Взвешенный скролл в `main` (`@/shared/lib/weighted-scroll`, в layout `/$lang`). Прежние причины отказа («Решения» этапа 6) проверены по одной. Где не сказано иное, проверка — в `e2e/weighted-scroll.spec.ts`.

- **Вес — снят.** Чанк `lenis` — 5,4 KB gzip. Он грузится после гейта ввода, только на `full` и с точным указателем. В загрузке страницы и в modulepreload его нет. Стартовый JS вырос на обвязку в чанке layout, около 0,9 KB gzip.
- **JS на каждом кадре — снят, но не так, как в прототипе.** Свой цикл Lenis (`autoRaf`) просит кадр на каждом vsync весь визит, даже когда страница стоит. Замер в headless Chromium на `/en/design`, 10 с покоя: с таким циклом 1,7 мс скрипта в секунду и около 73 % занятости главного потока, без него 0,4 мс и около 31 %. Поэтому `autoRaf: false`, и кадры идут только от колеса до конца скольжения. В покое Lenis стоит столько же, сколько его отсутствие: 0,4 мс в секунду, около 32 %. На главной сцена рисует каждый кадр сама. Замер скольжения (Chromium с GPU, CPU ×4, 1440×900, уровень `desktop`, главная вниз и вверх колесом по 70 px каждые 100 мс): с Lenis 58,1–58,3 fps, без него 55,5–58,3, p95 кадра 16,8 мс в обоих случаях.
- **Якоря — сняты.** `anchors: false`: skip link и «Back to top» прыгают по-браузерному и ставят фокус на `main`. Клавиша или нажатие посреди скольжения сначала останавливают Lenis. Иначе следующий кадр Lenis обрывает браузерную анимацию прокрутки: без этого Home посреди скольжения застревал в паре сотен пикселей от верха.
- **`scrollRestoration` — снят.** На смене страницы Lenis не крутит колесо (не `stop()`: тот глотает колесо целиком). Позицию ставит роутер. Через кадр после `onResolved` Lenis берёт её как есть. Back, Forward и перезагрузка приходят туда же, где без Lenis, и Lenis не тянет страницу к прежней цели. На главной с медленным API `settleScroll` дожимает позицию, пока страница растёт, и Lenis ему не мешает.
- **Поиск по странице — снят.** Lenis двигает само окно, поэтому Ctrl+F прыгает к совпадению. Прыжок посреди скольжения Lenis замечает (окно не там, куда он его ставил) и бросает свою цель, так что назад не возвращает. В e2e Ctrl+F не нажать, там тот же прыжок делает `scrollIntoView`. Живой Ctrl+F в Chrome агент не проверял.
- **Инерция тачпада — это и есть выбранный вес.** Тачпад шлёт колесо со своей инерцией, Lenis сглаживает её поверх. Владелец смотрел прототип на компьютере и выбрал `heavy`, сглаживание в `main` то же. Агент живой тачпад не проверял.
- **Касание — снято.** На `pointer: coarse` Lenis не грузится вовсе, а `syncTouch: false` оставляет касание браузеру и там, где точный указатель есть.

Кроме того: клавиатура (стрелки, Page Up/Down, пробел, Home/End) крутит по-браузерному. Под оверлеем Radix (`data-scroll-locked`) Lenis пропускает колесо, и Radix держит страницу сам. Колесо над блоком со своей прокруткой (плеер, выпадающий список) крутит этот блок (`allowNestedScroll`). Чанк, который не загрузился, оставляет браузерную прокрутку без следов в консоли.
