## Выбор: использовать

- Ржавчина `#B84530` — акцент в обеих темах. _Q27._
- Тёмная тема: `primary-text` `#DA6A52`, вторичный текст `#8A94A6`; токены `border`, `glow`. _Q27._
- Контраст текста AA. _[plan.md](plan.md)._
- Акцент сдержанный: графит доминирует; ржавчина — только главное действие, фокус, активный пункт навигации, ромбы. Свечение — только на hover/focus в тёмной теме. _Владелец, 2026-10-15._
- Углы: радиус 0; у ключевых элементов (карточки, главная кнопка) — срез угла под 45°, как грань ромба. _Владелец, 2026-10-15._
- Шрифты: обязательны казахская кириллица (ә ғ қ ң ө ұ ү һ і) и латиница с диакритикой; для `ar` — отдельный шрифт через `unicode-range`. _Q29, Q39._
- Темы: системная по умолчанию + переключатель. _Q17._
- RTL с первого дня; не зеркалятся лого, hero, плеер, блоки кода. _[ADR-0007](adr/0007-rtl-from-day-one.md), Q37._
- Анимации уважают `prefers-reduced-motion`. _[ADR-0005](adr/0005-motion-and-view-transitions.md)._

## Выбор: не допускать

- Surface без рамки: контраст Surface/BG ~1.12 — плоскости разделяются рамкой `border`. _Q20._
- Вторичный цвет `#4A5568` на тёмном фоне для текста (2.5:1) — только декор. _Q20._
- Светлая тема без акцента (Primary = Text). _Q20._
- Скруглённые «пилюли» и мягкие тени — противоречат острым граням. _Владелец, 2026-10-15._
- Постоянное свечение и ржавые заливки крупных блоков. _Владелец, 2026-10-15._

## Решения по ходу (2026-10-15)

- **Шрифты:** Tektur (заголовки), Onest (текст), Fira Code (код, метки), Readex Pro (`ar`). _Владелец._ Unbounded и JetBrains Mono отклонены: в их файлах (`@fontsource-variable` 5.3) нет ә ғ қ ң ұ һ — проверено по cmap.
- **`primary-text` в светлой теме — `#A83F2C`**, а не `#B84530`: исходная ржавчина на `surface-raised` даёт 4.31:1 (< AA). Заливки и кнопки остаются `#B84530`.
- **Hover главной кнопки — `#9A3826` в обеих темах**: светлый hover в тёмной теме не держит белый текст (4.39:1).
- **`glow` → `x-zsd.elevation.shadow-accent`** в цвете `primary-text` 40 %, только тёмная тема. Слово «glow» запрещено словарём формата, отдельный цвет-токен не нужен.
- **`border` → `x-zsd.border.color-default`** (`outline-muted`) и `color-control` (`outline`).
- **Disabled-текст — ≥ 4.5:1** (`#5F6672` / `#8C8C8C`), хотя WCAG этого не требует.

### Hero-эффект: Kinetic Grid

Выбран владельцем из пяти кандидатов OriginKit; Black Hole, Particle Tunnel, Fluid Trail и Pixel Reveal не прототипировались по решению владельца. Kinetic Grid — canvas 2D без зависимостей, не WebGL.

Сравнивались два варианта:

- **Оригинал OriginKit** (`kineticgrid`, вариант framer, MIT; получен через MCP OriginKit): квадратная сетка, каждый отрезок — отдельный `stroke()` со своей прозрачностью, точки — `arc()`, след курсора; DPR не ограничен; без курсора неподвижен; `cursor: crosshair`; reduced motion не учитывает. Цвета палитры, настройки по умолчанию (шаг 30, радиус 400).
- **Прототип** по той же идее: решётка повёрнута на 45°, ячейки — ромбы, под курсором заливаются ржавчиной; без курсора по сетке идёт волна; все линии — один путь и один `stroke()` за кадр. Шаг 48.

Замер: Chromium с GPU, указатель движется по сетке, частота экрана выше 60 Гц; gzip после esbuild minify, без React.

| | Оригинал, DPR 2 | Оригинал, DPR 1 | Прототип, DPR 1.5 | Прототип, DPR 1 |
|---|---|---|---|---|
| Вес gzip | 1.8 KB | | 1.2 KB | |
| 1440×900, CPU ×1 | 40 fps | 46 fps | 39 fps | 100 fps |
| 1440×900, CPU ×4 | 37 fps | 39 fps | 39 fps | 94 fps |
| 390×844, CPU ×4 | 100 fps | 100 fps | 88 fps | 100 fps |
| 390×844, CPU ×6 | 88 fps | 86 fps | 92 fps | 98 fps |

Выводы для #117:

- На большом вьюпорте оригинал упирается в ~2900 отдельных `stroke()` за кадр, и DPR 1 его не спасает. Отрезки рисуются пачками — одним путём, как в прототипе (или по корзинам прозрачности).
- Рисуем при DPR 1 (в пределах ADR-0006 «DPR ≤ 1.5»): тонкие линии и плоские заливки от этого не теряют.
- Берём из прототипа ромбическую решётку, заливку ячеек и волну без курсора; убираем `cursor: crosshair` (курсор не меняем) и след курсора; добавляем reduced motion и паузу вне вьюпорта.
- Замер — на GPU этой машины; слабый GPU проверяется в #125, FPS-проба ADR-0006 остаётся страховкой.

### Решения

- **Плавный скролл (Lenis): нет.** Вес и JS на каждом кадре, конфликты с якорями, `scrollRestoration` TanStack, поиском по странице и нативной инерцией тачпадов и мобильных. Вес движению дают reveal-анимации и кривые. ADR-0005 не меняется, отдельный ADR не нужен. _Владелец._
- **Кастомный курсор: нет** (по умолчанию `top-design`, согласия владельца нет).
- **Кривые:** expo out — вход, quart out — hover, expo in-out — перестановка ромбов, expo in — уход; ключевые слова `ease`/`linear` запрещены. Старые `easing-standard`/`easing-exit` заменены; `src/styles/tokens.css` перегенерируется и использования переводятся в #112.
- **Display:** `display-lg` 168px (10.5:1 к `body-md`), трекинг −0.04em, вес 800; ниже `lg` — `display-sm` 72px и ручной перенос «Web / Runner». Бренд латиницей во всех Lang, длинных kk/de слов в нём нет; переносы kk/de проверяются на заголовках страниц (`hyphens: auto`). Для Readex Pro трекинг 0.
- **Хедер:** всегда видим (единственный путь к меню), на главной лого пустое, пока ромбы в hero. **Футер:** контактная секция с крупным заголовком и почтой как главной ссылкой.
- **Детали:** `::selection` — `primary` + `on-primary` (5.3:1) в обеих темах; фокус — сплошной квадратный контур, на срезанных элементах идёт по срезу; hover карточки — рамка `primary`, ромб в срезанном углу, сдвиг заголовка на 4px, без теней и масштаба. Свечение остаётся только у главной кнопки в тёмной теме.

### Hero

- Высота: вьюпорт минус хедер (`svh`, чтобы не прыгал от панелей мобильного браузера), не меньше 480px.
- Асимметрия: бренд «WebRunner» от начального края контента; 7 ромбов лого — у его конечного края, на высоте прописных. Подзаголовок под брендом, с `lg` смещён на треть ширины контента: реальное имя (Brand) и заголовок из Profile, `body-lg`, `text-wrap: balance`.
- Главное действие — CV; второе — проекты.
- Бренд: `display-lg` 168px на `xl`, плавно (`clamp`) до `display-sm` 72px на 320px; ниже `lg` — две строки «Web» / «Runner», перенос вручную. Латиница и LTR во всех Lang.
- Эффект tier занимает весь hero за текстом и выходит за `content-max` до краёв вьюпорта; `aria-hidden`.
- Не зеркалятся эффект и раскладка ромбов внутри лого; текст, действия и место ромбов следуют Direction.

### Hero-эффект (tier `full`)

- Линии сетки — `outline-muted`, точки — `outline`; ячейки у указателя заливаются `primary` до 90% непрозрачности, как ромбы.
- Без указателя по сетке слева направо идёт медленная волна, так что на тач-экранах сетка тоже живёт. Hero не зеркалится, в `ar` направление то же.
- Canvas при DPR 1 (замер выше). `lite` — SVG-анимация ромбов лого, `static` — сетка неподвижной картинкой.

### Ритм главной

Плотные ↔ воздушные, крупные ↔ камерные секции, отступы не одинаковые:

1. **Hero** — воздушный, крупный: одно высказывание и пустой графит.
2. **Обо мне** — камерный: короткий абзац `body-lg` в `prose-max`, смещён как подзаголовок hero; сверху `section-lg`.
3. **Избранные проекты** — плотный, крупный: с `lg` одна широкая карточка, под ней две.
4. **Последние посты** — плотный, камерный: список из трёх (дата, заголовок), без обложек.
5. **Галерея** — воздушная: одна лента обложек альбомов, уходит за конечный край контента и прокручивается в своей области.
6. **Футер** — снова крупный: заголовок контактов закрывает страницу.

Заголовок секции — `headline-md` с индексом `label-mono` («02»); в конце секции — одна ссылка в её раздел.

### Хореография загрузки главной

Одна последовательность, заканчивается к `choreography-max` (1200 мс). Каждая анимация отвечает на вопрос «зачем она движется»: откуда вещь пришла, куда уходит или что отвечает пользователю; нет ответа — анимацию убрать. Движение — как масса, набирающая скорость: резкий старт, долгая мягкая остановка.

| Время | Что появляется |
|---|---|
| 0–200 мс | Структура: хедер, линии сетки hero, рамки |
| 200–600 мс | Слова бренда выезжают снизу из-под маски, через `stagger-word` (60 мс) |
| 200–700 мс | Ромбы лого собираются по одному у конца бренда, `easing-layout` |
| 400–800 мс | Подзаголовок |
| 600–900 мс | Действия и контролы хедера, через `stagger-item` (80 мс) |
| 800–1200 мс | Остальное: запускается эффект hero, первая секция под сгибом |

- Строки и слова выезжают из-под маски, не проявляются блоком.
- Другие страницы так же показывают только заголовок страницы.
- Секции под сгибом появляются один раз при входе во вьюпорт, элементы внутри — через `stagger-item`.
- Ничего не блокирует ввод: ссылки и кнопки работают во время последовательности.
- От позиции скролла зависит только декор (ромбы в хедер); текст со скроллом не движется.
- Reduced motion: сразу конечное состояние; контент никогда не остаётся скрытым, если анимация не запустилась.

### Детали

- **Hover карточки:** рамка `primary`, ромб в срезанном углу, заголовок сдвигается на 4px по направлению чтения; `duration-fast`, `easing-hover`. Без масштаба и без теней.
- **Фокус:** сплошной контур с квадратными углами, `focus-width`/`focus-offset`/`focus-color`, без перехода. На срезанных элементах контур рисуется на внутреннем слое или SVG рамки и идёт по срезу, а не прямоугольником вокруг.
- **`::selection`:** `on-primary` на `primary` (5.3:1) в обеих темах, в блоках кода тоже.
- **Типографика:** `hyphens: auto` и `overflow-wrap: anywhere` на заголовках страниц — проверить kk/de на 320px; для Readex Pro трекинг 0.
