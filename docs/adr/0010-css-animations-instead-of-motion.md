# 0010. CSS-анимации вместо Motion

- Статус: принято, заменяет библиотеку Motion из ADR-0005 (View Transitions остаются)
- Дата: 2026-10-29

## Контекст
Бюджет #142: performance ≥ 90, LCP < 2,5 с, JS ≤ 150 KB на каждой публичной странице (Lighthouse, mobile). Motion (`motion/react`) использовали только `Reveal` и `RevealText`, но он стоил ~31 KB gzip на каждой странице: ядро `m` (~14 KB) и чанк `features` (~18 KB), который грузился сразу после первой отрисовки и попадал в замер. Меню и плеер уже анимируются на CSS и Web Animations.

## Решение
Анимаций без библиотеки. `Reveal` и `RevealText` — CSS keyframes (`reveal-*` в `index.css`) на токенах DESIGN.md; IntersectionObserver только переключает класс, смещения и задержка — CSS-переменные. `prefers-reduced-motion` читает `usePrefersReducedMotion()`, под ним рендерится конечное состояние. Где анимацией должен управлять скрипт — Web Animations API.

## Альтернативы
- Оставить Motion, но грузить `features` позже — Lighthouse всё равно считает их в JS страницы, а ядро `m` остаётся в начальном.
- GSAP — тяжелее Motion.

## Последствия
- −31 KB JS на каждой странице, нет зависимости `motion`.
- Пружины, layout-анимации и жесты Motion недоступны; если понадобятся, это новое решение с ценой в бюджете #142.
- Правило ESLint про `ease` в `transition` Motion снято вместе с библиотекой; кривые в классах по-прежнему проверяются.
