# 0011. Markdown рендерится на Worker

- Статус: принято
- Дата: 2026-10-29

## Контекст
Бюджет #142: JS ≤ 150 KB на каждой публичной странице. Страницы с Markdown (Case Study, пост) грузили react-markdown + GFM (~48 KB gzip) и Shiki с грамматикой (~57 KB), итого ~270 KB. Shiki нельзя отложить: блок кода часто на первом экране, и Lighthouse всё равно считает всё, что загрузилось с открытием страницы.

## Решение
Public API отдаёт `caseStudy` и `body` поста не текстом, а деревом (`contracts/markdown/`): Worker разбирает Markdown (unified + GFM), чистит его (только разрешённые теги и атрибуты, без raw HTML и небезопасных URL), сдвигает заголовки и раскрашивает блоки кода Shiki. Браузер только рисует дерево (`Markdown` из `@/shared/ui/markdown`, ~1,5 KB). Превью в админке строит дерево той же функцией в браузере: парсер и Shiki там грузятся лениво. В D1 и Admin API — по-прежнему текст.

## Альтернативы
- Лёгкий подсветчик в браузере (highlight.js, Prism) — всё равно десятки KB и другая палитра, AA-контраст пришлось бы проверять заново; парсер Markdown остаётся.
- Рендер при сохранении в админке с хранением дерева в D1 — нужна миграция, переводы и сиды тоже должны его строить.
- SSR страниц целиком — против ADR-0001.

## Последствия
- Страницы с Markdown весят как остальные (~132 KB вместо ~270 KB).
- Worker тяжелее (Shiki с грамматиками, ~2,7 MB несжатого кода) и тратит CPU на рендер; изолят помнит последние 64 тела.
- Формат дерева — контракт API: новый тег Markdown нужно добавить в `MARKDOWN_TAGS` и в `Markdown`, иначе от него останется только текст.
